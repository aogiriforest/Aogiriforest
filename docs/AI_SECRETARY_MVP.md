# AI秘書 MVP 設計 v1.0
更新: 2026-10-26
所属: アオギリフォレストAI本部 / 代表直属

## 最初の目標
最小構成のAI本部（秘書・営業・リサーチ・経理）の入口として、代表の自然言語の指示を一件ずつ受付・整理・担当割当し、結果を代表に戻す。まずは一連の流れが動くことを優先し、専門AIや機能を増やしすぎない。

## 秘書の仕事
1. 代表からの指示を受ける（音声・テキスト）
2. 依頼の目的、成果物、期限、対象を抽出。必須情報が欠けるときだけ一問確認
3. 営業・リサーチ・経理の担当に振り分け、複数部門の連携順を決める
4. 案件の状態（受付・調査中・制作中・確認待ち・完了・保留）を管理
5. 代表に要点と次に必要な判断を簡潔に報告
6. 承認済みの成果物と根拠・履歴を整理

## ルーティング例
- 「協力先の商品のnoteを作って」→リサーチが事実収集→営業内広報・プレゼン制作室が下書き→秘書が代表確認へ
- 「国内ヴィーガン市場を調べて」→総合リサーチ部→秘書が要点報告
- 「今月の利益を確認して」→経理財務部。実データがなければ未接続・未確認と伝え、数値を作らない
- 「新しい農家を登録」→協力先登録案件。個人情報は非公開保管、未実装なら登録完了と偽らない

## 最小案件データ
案件ID、受付日時、原文、目的、担当、期限（任意）、状態、参照資料、成果物、承認要否、承認結果、最終更新。

## 必須ガードレール
- 公開・送信・契約・発注・支払・データ削除は明示的な代表承認を要する
- 連絡先・顧客・取引・財務の機密情報は公開GitHubに置かない
- 実際に実行していない作業を完了と報告しない
- 動物性原料不使用、五葷不使用、アルコール0.5%以下は商品に関して検証してから表示
- 根拠不明の断定・架空の取材・架空の数値は禁止

## 最初の動作テスト
入力「この商品の特徴を調べてnote下書きを作って」
期待: 案件受付→対象商品が不明なら一問確認→リサーチ依頼→事実と未確認の区別→営業制作室で下書き→代表承認待ち。公開しない。
